# Chococo（AIスイーツ×ドリンクペアリングアプリ） 要件定義書

作成日：2026年7月20日（初版）
最終更新日：2026年8月15日（8章を、後続の設計ドキュメントで確定した内容に更新）

## 1. 概要

### 1.1 背景・目的

食べたいスイーツに合う飲み物（主にコーヒー）をAIが提案してくれるWebアプリケーションを開発する。あわせて、食べたスイーツの記録をインスタグラム風のUIで残せる機能を提供し、日々のスイーツ体験を記録・振り返られるサービスを目指す。

本アプリはスクール課題として開発するものであり、技術要件としてJava（Spring Boot）およびReactの使用が必須となる。

### 1.2 プロジェクト概要

| 項目 | 内容 |
|---|---|
| アプリ名 | Chococo（チョコ×コーヒーの組み合わせに由来） |
| 開発期間 | 約1ヶ月 |
| 公開先 | AWS（無料枠内での運用を想定） |
| 想定ユーザー | 複数ユーザー（一般公開・テスト利用を想定） |

### 1.3 類似サービス・差別化ポイント

類似の要素を持つ既存サービスとして、以下のようなものがある。

- **PostCoffee**：質問に回答すると、多数の組み合わせの中からAIが好みのコーヒーを選んでくれるサブスクリプションサービス。質問診断型で、スイーツ名からの自由な提案ではない。
- **root C MATCH**：無人カフェのアプリに搭載された、質問に答えることでその人に合うコーヒーを提案するAI診断機能。こちらも診断型。
- **CoffeePad**：テイスティングノートを記録し、カレンダーで振り返れるコーヒー記録アプリ。「記録＋カレンダー」は近いが、ペアリング提案機能は持たない。

これらに対し、Chococoは「食べたいスイーツ／飲みたいコーヒーを起点に、AIが理由つきで双方向にペアリングを提案し、その結果を記録として残せる」点が差別化ポイントとなる。

## 2. 対象ユーザー

- スイーツ好きで、合う飲み物（コーヒー等）を知りたい一般ユーザー
- 食べたスイーツの記録を残し、後から振り返りたいユーザー
- （開発時点）スクールの評価者・テストユーザー

## 3. 機能要件

### 3.1 MVP（フェーズ1で実装する機能）

開発優先度：ペアリング提案機能を先に実装し、その後に記録機能を実装する。

| No. | 機能名 | 概要 |
|---|---|---|
| 1 | ユーザー認証 | メールアドレス＋パスワードによる新規登録・ログイン。JWTを発行し、以降のAPIリクエストの認証に使用する。 |
| 2 | ペアリング提案（スイーツ→コーヒー） | 食べたいスイーツ名（テキスト）を入力すると、外部AI API（Claude/OpenAI等）を呼び出し、あらかじめ用意されたコーヒー豆の種類リストの中から最適なものをAIが選び、理由とあわせて提示する。 |
| 3 | スイーツ記録の保存 | 写真・スイーツ名・日付・感想（コメント）を記録として保存する。AIペアリング提案を経由した場合はその提案結果（コーヒー豆名・理由）もあわせて保存できる（AI提案は必須ではなく、記録単体での保存も可能）。 |
| 4 | 記録一覧表示 | 保存した記録をカレンダー形式の見た目で一覧表示する（インスタグラム風のUIを想定）。1日に複数記録がある場合は件数バッジやサムネイル並びで表示する。 |
| 5 | 記録の編集・削除 | 自分が保存した記録のスイーツ名・写真・感想を編集、または記録自体を削除できる。 |

### 3.2 拡張機能（フェーズ2以降・今回の実装範囲外）

- 逆方向のペアリング提案（コーヒー→スイーツ）：飲みたいコーヒーの種類から、合うスイーツをAIが提案する双方向対応
- コーヒー以外の飲み物（紅茶など）への対応拡大
- スイーツ写真のS3への本格保存
- Instagramとの連携（外部投稿の取得・連携表示）※Meta社の審査・ビジネスアカウント登録が必要なため、要件を別途精査する

## 4. 非機能要件

| 区分 | 内容 |
|---|---|
| 認証 | JWTアクセストークン＋リフレッシュトークンによるトークン認証（Spring Security + JWTライブラリ）。詳細は[auth-design.md](./auth-design.md)参照 |
| データベース | AWS RDS（MySQL）※無料枠は12ヶ月限定のため運用期間に注意。詳細は[tech-stack.md](./tech-stack.md)・[aws-infra-design.md](./aws-infra-design.md)参照 |
| 画像保存 | 本番も含めEC2ローカルディスク（EBS）に保存する。将来的にS3へ移行可能な設計とする（詳細は[aws-infra-design.md](./aws-infra-design.md)参照） |
| 対応デバイス | スマートフォンでも見やすいレスポンシブデザインに対応する |
| インフラ費用 | AWS無料枠の範囲内での運用を前提とする |
| 外部API利用 | AI API（Claude/OpenAI等）の呼び出し回数・料金プランは別途検討する |

## 7. AI API連携の設計方針

| 項目 | 方針 |
|---|---|
| 呼び出し方式 | ReactからSpring Boot経由でAI APIを呼び出す。APIキーはサーバー側のみで管理し、フロントエンドには一切露出させない。 |
| 呼び出しタイミング | 「AIペアリング提案」ボタン押下時に単発でAPIを呼び出す方式とする。チャットのような会話履歴の保持・再送信は行わない。 |
| 利用上限 | ユーザー1人あたり1日10回までを上限とする（日本時間＝JSTの0時を基準に1日をリセット）。 |
| コスト管理 | 出力トークン数の上限を指定して想定外の高額請求を防ぐ。月次の予算アラートを設定する。 |
| モデル選定 | まずは低コストなモデル（Haiku級）で精度を検証し、必要に応じて上位モデルへの切り替えを検討する。 |

参考：1日10回の利用上限を、利用者10〜15名が7日間フルに使い切ったと仮定した場合の概算費用（1回あたり入力500トークン・出力300トークンと仮定）。実際の利用はこれより少なくなる見込み。

| モデル | 総呼び出し回数（700〜1050回）の概算費用 |
|---|---|
| Claude Haiku 4.5 | 約1.4〜2.1ドル（約230〜340円） |
| Claude Sonnet 5（導入価格） | 約2.8〜4.2ドル（約450〜680円） |
| Claude Sonnet 5（標準価格） | 約4.2〜6.3ドル（約680〜1,020円） |

※為替は1ドル＝約162円で概算（2026年7月時点）。金額はあくまで目安であり、実際のプロンプト長や利用実績により変動する。
